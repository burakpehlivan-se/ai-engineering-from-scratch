# एमसीपी नमूनाकरण  सर्वर-अनुरोधित एलएलएम पूर्णता और एजेंट लूप

> अधिकांश MCP सर्वर मूर्ख निष्पादक हैंः तर्क ले, कोड चलाएं, सामग्री लौटाएं। नमूना लेने से सर्वर दिशा बदल सकता हैः यह ग्राहक के LLM से निर्णय लेने के लिए कहता है। यह सर्वर के पास किसी भी मॉडल क्रेडेंशियल के बिना सर्वर-होस्ट एजेंट लूप को सक्षम बनाता है। एसईपी-1577, 2025-11-25 में विलय हुआ, नमूने लेने के अनुरोधों के अंदर उपकरण जोड़े ताकि लूप में गहरी तर्क शामिल हो सके। ड्रिफ्ट-रिस्क नोटः एसईपी-1577 टूल-इन-सैंपलिंग फॉर्म 1 Q2026 तक प्रयोगात्मक था और अभी भी एसडीके एपीआई में बसता है।

**Type:** Build
**Languages:** Python (stdlib, sampling harness)
**Prerequisites:** Phase 13 · 07 (MCP server), Phase 13 · 10 (resources and prompts)
**Time:** ~75 minutes

## सीखने के लक्ष्य

- क्या समझाओ `sampling/createMessage`हल करता है (सर्वर-होस्ट किए गए लूप्स सर्वर-साइड एपीआई कुंजी के बिना) ।
- एक सर्वर को लागू करें जो क्लाइंट को एक बहु-टर्न प्रॉम्प्ट पर नमूना करने के लिए कहता है और पूरा करता है।
- उपयोग करें`modelPreferences`(लागत / गति / खुफिया प्राथमिकताएं) ग्राहक मॉडल चयन का मार्गदर्शन करने के लिए।
- एक बनाओ `summarize_repo`उपकरण जो आंतरिक रूप से सख्त-कोडिंग व्यवहार के बजाय नमूनाकरण के माध्यम से पुनरावृत्ति करता है।

## समस्या

कोड-सारांश कार्यप्रवाह के लिए एक उपयोगी एमसीपी सर्वर को फ़ाइल ट्री पर चलने, पढ़ने के लिए कौन सी फ़ाइलें चुनने, सारांश संश्लेषण करने और लौटना चाहिए। एलएलएम तर्क कहां होता है?

विकल्प A: सर्वर अपना LLM बुलाता है। एक एपीआई कुंजी की आवश्यकता होती है, सर्वर पक्ष में बिल करता है, प्रति उपयोगकर्ता महंगा है।

विकल्प बीः सर्वर कच्चे सामग्री वापस करता है; क्लाइंट का एजेंट तर्क करता है। काम करता है लेकिन क्लाइंट प्रॉम्प्ट में सर्वर तर्क को स्थानांतरित करता है, जो नाजुक है।

विकल्प C: सर्वर ग्राहक के LLM के माध्यम से पूछता है `sampling/createMessage`. सर्वर एल्गोरिथ्म (कौन सी फ़ाइलें पढ़नी हैं, कितने पास करना है) को बनाए रखता है जबकि क्लाइंट बिलिंग और मॉडल विकल्प को बनाए रखता है। सर्वर के पास कोई क्रेडेंशियल नहीं है।

नमूनाकरण विकल्प सी है। यह तंत्र है जिसके द्वारा एक विश्वसनीय सर्वर एक पूर्ण एलएलएम होस्ट होने के बिना एक एजेंट लूप होस्ट कर सकता है।

## अवधारणा

### `sampling/createMessage`अनुरोध

सर्वर भेजता हैः

```json
{
  "jsonrpc": "2.0",
  "id": 42,
  "method": "sampling/createMessage",
  "params": {
    "messages": [{"role": "user", "content": {"type": "text", "text": "..."}}],
    "systemPrompt": "...",
    "includeContext": "none",
    "modelPreferences": {
      "costPriority": 0.3,
      "speedPriority": 0.2,
      "intelligencePriority": 0.5,
      "hints": [{"name": "claude-3-5-sonnet"}]
    },
    "maxTokens": 1024
  }
}
```

ग्राहक अपना LLM चलाता है, देता हैः

```json
{"jsonrpc": "2.0", "id": 42, "result": {
  "role": "assistant",
  "content": {"type": "text", "text": "..."},
  "model": "claude-3-5-sonnet-20251022",
  "stopReason": "endTurn"
}}
```

### `modelPreferences`

तीन फ्लोट्स जो 1.0 तक होते हैंः

- `costPriority`: सस्ते मॉडल की ओर रुख करें।
- `speedPriority`: तेज मॉडल की ओर रुख करें।
- `intelligencePriority`: अधिक सक्षम मॉडल की ओर रुख करें।

और `hints`ग्राहक सुझावों का सम्मान कर सकता है या नहीं; ग्राहक का उपयोगकर्ता कॉन्फ़िगरेशन हमेशा जीतता है।

### `includeContext`

तीन मान:

- `"none"` केवल सर्वर द्वारा आपूर्ति संदेशों. डिफ़ॉल्ट.
- `"thisServer"` इस सर्वर के सत्र से पहले के संदेशों को शामिल करें।
- `"allServers"` सभी सत्र संदर्भ को शामिल करें।

`includeContext`2025-11-25 के बाद से यह नरम-अवशिष्ट है क्योंकि यह क्रॉस-सर्वर संदर्भ लीक करता है, जो सुरक्षा चिंता है।`"none"`और संदेशों में स्पष्ट संदर्भ पारित करें।

### उपकरण से नमूनाकरण (SEP-1577)

2025-11-25 में नयाः नमूना लेने के अनुरोध में एक `tools`क्लाइंट उन उपकरणों का उपयोग करके एक पूर्ण उपकरण-कॉलिंग लूप चलाता है। यह सर्वर को क्लाइंट के मॉडल के माध्यम से एक ReAct शैली एजेंट लूप होस्ट करने की अनुमति देता है।

```json
{
  "messages": [...],
  "tools": [
    {"name": "fetch_url", "description": "...", "inputSchema": {...}}
  ]
}
```

क्लाइंट लूप्सः नमूना, निष्पादित करें उपकरण यदि बुलाया गया है, फिर से नमूना, अंतिम सहायक संदेश लौटाएं। यह 1 Q2026 तक प्रयोगात्मक है; SDK हस्ताक्षर अभी भी बह सकते हैं। कार्यान्वयन करते समय 2025-11-25 विनिर्देश के क्लाइंट / नमूनाकरण अनुभाग के खिलाफ पुष्टि करें।

### मानव-सर्प में

क्लाइंट को नमूना चलाने से पहले उपयोगकर्ता को यह दिखाना चाहिए कि सर्वर नमूना को क्या करने के लिए कह रहा है। एक दुर्भावनापूर्ण सर्वर उपयोगकर्ता के सत्र को हेरफेर करने के लिए नमूना का उपयोग कर सकता है ("उपयोगकर्ता को एक्स कहें ताकि वे Y पर क्लिक करें") । क्लाउड डेस्कटॉप, वीएस कोड और कर्सर सतह नमूना अनुरोध एक पुष्टि संवाद के रूप में उपयोगकर्ता इनकार कर सकता है।

2026 में सहमतिः मानव की पुष्टि के बिना नमूना लेना लाल झंडे है। गेटवे (चरण 13 · 17) कम जोखिम वाले नमूना लेने को स्व-अनुमोदित कर सकते हैं और संदिग्ध किसी भी चीज़ से स्व-नकार सकते हैं।

### एपीआई कुंजी के बिना सर्वर होस्ट किए गए लूप

कैनोनिक उपयोग मामलाः कोड-संक्षेप एमसीपी सर्वर जिसमें कोई एलएलएम एक्सेस नहीं है। यह करता हैः

1. रेपो संरचना पर चलें।
2. कॉल`sampling/createMessage`"इस रेपो के उद्देश्य का वर्णन करने के लिए पांच फ़ाइलों का चयन सबसे अधिक संभावना है। "
3. उन फ़ाइलों को पढ़ें.
4. कॉल`sampling/createMessage`फ़ाइलों की सामग्री के साथ और "रिपो को 3 पैराग्राफ में सारांशित करें।"
5. सारांश को एक के रूप में लौटाएँ `tools/call`परिणाम।

सर्वर कभी LLM एपीआई को छूता नहीं है। ग्राहक का उपयोगकर्ता अपनी क्रेडेंशियल का उपयोग करके पूर्णता के लिए भुगतान करता है।

### सुरक्षा जोखिम (इकाई 42 का खुलासा, 2026 Q1)

- **Covert sampling.**एक उपकरण जो हमेशा "सत्र संदर्भ से उपयोगकर्ता के ईमेल के साथ प्रतिक्रिया" के साथ नमूनाकरण को बुलाता है। " चरण 13 · 15 हमले के वेक्टरों को कवर करता है।
- **Resource theft via sampling.**सर्वर क्लाइंट से हमलावर के उपयोगिता भार का सारांश देने के लिए कहता है, उपयोगकर्ता को बिल देता है।
- **Loop bombs.**सर्वर एक तंग लूप में नमूना बुलाता है. ग्राहकों को प्रति सत्र दर सीमाओं को लागू करना चाहिए.

```figure
t3-sampling-flip
```

## इसका प्रयोग करें

`code/main.py`एक सिम्युलेटेड "समुचित_रेपो" उपकरण दो नमूनाकरण राउंड (पिक-फाइल, फिर सारांश) को बुलाता है, और नकली क्लाइंट डिब्बाबंद प्रतिक्रियाओं को वापस देता है। हर्नस दिखाता हैः

- सर्वर भेजता है `sampling/createMessage`के साथ`modelPreferences`. .
- ग्राहक एक पूरा लौटाता है।
- सर्वर अपना लूप जारी रखता है।
- दर सीमा प्रति उपकरण कॉल कुल नमूना कॉल को सीमित करता है।

क्या देखना हैः

- सर्वर केवल एक उपकरण को उजागर करता है (`summarize_repo`); सभी तर्क नमूना लेने के कॉल में होता है।
- मॉडल वरीयताएं ग्राहक के मॉडल विकल्प का वजन करती हैं; सुझाव पसंदीदा मॉडल सूचीबद्ध करते हैं।
- लूप समाप्त होता है `stopReason: "endTurn"`. .
- `max_samples_per_tool = 5`सीमा एक भागने वाला लूप पकड़ता है।

## प्रमुख शर्तें

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Sampling | "Server-to-client LLM call" | Server asks client's model for a completion |
| `sampling/createMessage` | "The method" | JSON-RPC method for sampling requests |
| `modelPreferences` | "Model priorities" | Cost / speed / intelligence weights plus name hints |
| `includeContext` | "Cross-session leakage" | Soft-deprecated context inclusion mode |
| SEP-1577 | "Tools in sampling" | Allow tools inside sampling for server-hosted ReAct |
| Human-in-the-loop | "User confirms" | Client surfaces sampling request to user before running |
| Loop bomb | "Runaway sampling" | Server-side infinite sampling loop; client must rate-limit |
| Covert sampling | "Hidden reasoning" | Malicious server hides intent in sampling prompts |
| Resource theft | "Using user's LLM budget" | Server forces client to spend on sampling it does not want |
| `stopReason` | "Why generation halted" | `endTurn`, `stopSequence`, or `maxTokens` |
