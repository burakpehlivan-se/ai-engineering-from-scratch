# जड़ें और उत्प्रेरणा  परिधि और उड़ान के मध्य में उपयोगकर्ता इनपुट

> हार्ड-कोडेड पथ उस क्षण टूट जाते हैं जब कोई उपयोगकर्ता एक अलग प्रोजेक्ट खोलता है। पूर्व-भरी उपकरण तर्क टूट जाते हैं जब उपयोगकर्ता कम निर्दिष्ट करता है। रूट सर्वर को यूआरआई के उपयोगकर्ता नियंत्रित सेट तक पहुंचाते हैं; एक फॉर्म या यूआरएल के माध्यम से उपयोगकर्ता से संरचित इनपुट के लिए पूछने के लिए टूल कॉल के बीच में निष्कासन रुक जाता है। दो क्लाइंट आदिम, दो सामान्य MCP विफलता मोड के लिए फिक्स. एसईपी-1036 (URL-मोड निकासी, 2025-11-25) इसके आधार पर निर्भर करने से पहले एच 1 2026  एसडीके संस्करणों की जांच के माध्यम से प्रयोगात्मक है।

**Type:** Build
**Languages:** Python (stdlib, roots + elicitation demo)
**Prerequisites:** Phase 13 · 07 (MCP server)
**Time:** ~45 minutes

## सीखने के लक्ष्य

- घोषणा `roots`और प्रतिक्रिया`notifications/roots/list_changed`. .
- घोषित रूट सेट के अंदर यूआरआई पर सर्वर फ़ाइल संचालन को सीमित करें।
- उपयोग करें`elicitation/create`उपयोगकर्ता से टूल कॉल के बीच में पुष्टि या संरचित इनपुट के लिए पूछना।
- फॉर्म मोड और यूआरएल मोड इलिकिटेशन के बीच चयन करें (बाद में प्रयोगात्मक है; ड्रिफ्ट-रिस्क नोट किया गया है) ।

## समस्या

दो ठोस विफलताएं एक नोट्स एमसीपी सर्वर उत्पादन में हिट।

**Broken path assumption.**सर्वर के खिलाफ लिखा है `~/notes`. एक उपयोगकर्ता पर एक अलग मशीन में नोट्स के साथ `~/Documents/Notes`एक उपकरण कॉल प्राप्त करता है जो चुपचाप विफल रहता है (कोई फ़ाइल नहीं मिली) या इससे भी बदतर, गलत जगह पर लिखा गया है।

**Missing argument the user would know.**उपयोगकर्ता पूछता है "पुराना TPS रिपोर्ट नोट को हटा दें। मॉडल कॉल करता है `notes_delete(title: "TPS report")`लेकिन 2023, 2024 और 2025 के तीन मेल खाते नोट हैं। उपकरण अनुमान नहीं लगा सकता। "अवास्तविक" के साथ विफल होना कष्टप्रद है; तीनों पर चलना विनाशकारी है।

मूल पहले तयः ग्राहक घोषणा करता है `initialize`सर्वर यूआरआई का सेट स्पर्श कर सकता है. उत्तेजना दूसरे को ठीक करता हैः सर्वर टूल कॉल को रोकता है और भेजता है `elicitation/create`उपयोगकर्ता से यह पूछने के लिए कि कौन सा चुनें।

## अवधारणा

### जड़ें

ग्राहक रूट लिस्ट को  पर घोषित करता है`initialize`:

```json
{
  "capabilities": {"roots": {"listChanged": true}}
}
```

सर्वर फिर कॉल कर सकते हैं `roots/list`:

```json
{"roots": [{"uri": "file:///Users/alice/Documents/Notes", "name": "Notes"}]}
```

सर्वर को रूट को सीमा के रूप में व्यवहार करना चाहिएः रूट सेट के बाहर पढ़ी या लिखी गई किसी भी फ़ाइल को अस्वीकार कर दिया जाता है। यह क्लाइंट द्वारा लागू नहीं किया जाता है (सर्वर अभी भी उपयोगकर्ता द्वारा भरोसा किया गया कोड है), लेकिन विशिष्टता अनुरूप सर्वर इसे सम्मान करते हैं।

जब उपयोगकर्ता एक जड़ जोड़ता है या हटाता है, क्लाइंट भेजता है `notifications/roots/list_changed`सर्वर फिर से कॉल करता है`roots/list`और उसकी सीमा को अद्यतन करता है।

### क्यों जड़ें एक ग्राहक आदिम हैं

रूट क्लाइंट द्वारा घोषित की जाती है क्योंकि वे उपयोगकर्ता के सहमति मॉडल का प्रतिनिधित्व करते हैं। उपयोगकर्ता ने क्लाउड डेस्कटॉप को बताया "इस नोट सर्वर को इन दो निर्देशिकाओं तक पहुंच दें। सर्वर उस दायरे को नहीं बढ़ा सकता है।

### उद्भवः फॉर्म मोड डिफ़ॉल्ट

`elicitation/create`एक रूप योजना और एक प्राकृतिक भाषा प्रलोभन लेता हैः

```json
{
  "method": "elicitation/create",
  "params": {
    "message": "Delete 'TPS report'? Multiple notes match; pick one.",
    "requestedSchema": {
      "type": "object",
      "properties": {
        "note_id": {
          "type": "string",
          "enum": ["note-3", "note-7", "note-14"]
        },
        "confirm": {"type": "boolean"}
      },
      "required": ["note_id", "confirm"]
    }
  }
}
```

ग्राहक एक फॉर्म प्रस्तुत करता है, उपयोगकर्ता का उत्तर एकत्र करता है, देता हैः

```json
{
  "action": "accept",
  "content": {"note_id": "note-14", "confirm": true}
}
```

तीन संभावित कार्य:`accept`(उपयोगकर्ता ने इसे भर दिया), `decline`(उपयोगकर्ता ने इसे बंद कर दिया), `cancel`(उपयोगकर्ता ने पूरे उपकरण कॉल को बंद कर दिया है).

फॉर्म योजनाएं सपाट हैं  नेस्टेड ऑब्जेक्ट v1 में समर्थित नहीं हैं। SDK आमतौर पर एकल परत से अधिक जटिल कुछ भी अस्वीकार करते हैं।

### निकासीः URL मोड (SEP-1036, प्रयोगात्मक)

2025-11-25 में नया। एक योजना के बजाय, सर्वर एक URL भेजता हैः

```json
{
  "method": "elicitation/create",
  "params": {
    "message": "Sign in to GitHub",
    "url": "https://github.com/login/oauth/authorize?client_id=..."
  }
}
```

ग्राहक ब्राउज़र में URL खोलता है, पूरा होने का इंतजार करता है, उपयोगकर्ता वापस आने पर वापस आता है। OAuth प्रवाह, भुगतान प्राधिकरण और दस्तावेज़ हस्ताक्षर के लिए उपयोगी है जहां एक फॉर्म अपर्याप्त है।

ड्रिफ्ट-रिस्क नोटः एसईपी-1036 प्रतिक्रिया आकार अभी भी तय है; कुछ एसडीके कॉलबैक यूआरएल वापस करते हैं, अन्य एक पूरा टोकन वापस करते हैं। उत्पादन में यूआरएल मोड का उपयोग करने से पहले अपने एसडीके के रिलीज नोट पढ़ें।

### जब उत्प्रेरणा सही उपकरण है

- विनाशकारी कार्यों से पहले उपयोगकर्ता पुष्टि (विनाशकारी संकेत + उत्तेजना) ।
- स्पष्टीकरण (N मैचों में से एक चुनें) ।
- पहली बार सेटअप (एपीआई कुंजी, निर्देशिका, वरीयताएं)
- OAuth शैली प्रवाह (URL मोड)

### जब उत्प्रेरणा गलत हो

- एक उपकरण के आवश्यक तर्क भरना जो मॉडल गद्य में मांग सकता था। एक सामान्य पुनः प्रम्प्ट का उपयोग करें, एक उत्प्रेरक संवाद नहीं।
- उच्च आवृत्ति कॉल। प्रवर्तक वार्तालाप को बाधित करता है; इसे लूप के अंदर न चलाएं।
- सर्वर तथ्य के बाद सत्यापित कर सकता है कुछ भी सत्यापित करें, एक त्रुटि वापस, मॉडल पाठ में उपयोगकर्ता पूछने दें.

### मानव-संचल में पुल

इल्तिजा और नमूनाकरण एक साथ MCP के "मानव-इन-द-लूप" मॉडल को सक्षम करते हैं। एक सर्वर का एजेंट लूप उपयोगकर्ता इनपुट (इल्तिजा) या मॉडल तर्क (सैंपलिंग) के लिए ठहराव कर सकता है। चरण 13 · 11 में नमूने शामिल हैं; यह सबक इल्तिजा को कवर करता है। उन्हें पूर्ण मध्य-लूप नियंत्रण के लिए एक साथ रखें।

```figure
t3-roots-boundary
```

## इसका प्रयोग करें

`code/main.py`नोट सर्वर को बढ़ाता हैः

- `roots/list`रूट लिस्ट में बदलाव किए गए सूचनाओं के बाद सर्वर द्वारा पुनः पूछे जाने वाले उत्तर।
- ए `notes_delete`उपकरण जो उपयोग करता है `elicitation/create`कई नोटों के मिलान पर स्पष्टता का उपयोग करना।
- ए `notes_setup`एक उपकरण जो URL- मोड निष्कर्षण का उपयोग एक प्रथम रन कॉन्फ़िग पेज (अनुकरण) खोलने के लिए करता है।
- सीमा जांच जो घोषित जड़ों के बाहर यूआरआई पर संचालन से इनकार करती है।

डेमो में तीन परिदृश्य हैंः खुश पथ (एक मैच), असंबद्धता (तीन मैच, उत्प्रेरक आग), आउट-ऑफ-रूट-लेखन (अस्वीकृत) ।

## इसे भेजें

यह सबक हमें फल देता है`outputs/skill-elicitation-form-designer.md`. किसी ऐसे उपकरण को देखते हुए जिसे उपयोगकर्ता की पुष्टि या स्पष्टीकरण की आवश्यकता हो सकती है, कौशल इलिकिट फॉर्म स्कीम और संदेश टेम्पलेट को डिजाइन करता है।

## व्यायाम

1. दौड़ें`code/main.py`. विसंगति पथ को ट्रिगर करें; पुष्टि करें कि अनुकरण उपयोगकर्ता उत्तर उपकरण पर वापस रुट किया जाता है.

2. एक नया उपकरण जोड़ें `notes_archive`UX की जांच करेंः यह पाठ में मॉडल फिर से पूछने की तुलना में कैसे होता है?

3. पहली बार ओएथ प्रवाह के लिए URL मोड निष्कासन लागू करें। ड्रीफ जोखिम को ध्यान में रखें और एक एसडीके संस्करण गार्ड जोड़ें।

4. विस्तार `roots/list`संभालः जब कोई सूचना आती है, तो सर्वर को परमाणु रूप से फिर से पढ़ना चाहिए और खुली फ़ाइल हैंडल को फिर से स्कैन करना चाहिए जो अब दायरे से बाहर हो सकते हैं।

5. GitHub पर SEP-1036 मुद्दे चर्चा धागा पढ़ें। एक खुला प्रश्न की पहचान करें जो प्रभावित करता है कि सर्वर को URL मोड कॉलबैक को कैसे संभालना चाहिए।

## प्रमुख शर्तें

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Root | "Consent boundary" | URI the client has allowed the server to touch |
| `roots/list` | "Server asks for scope" | Client returns the current root set |
| `notifications/roots/list_changed` | "User changed scope" | Client signals the root set has mutated |
| Elicitation | "Ask the user mid-call" | Server-initiated request for structured user input |
| `elicitation/create` | "The method" | JSON-RPC method for elicitation requests |
| Form mode | "Schema-driven form" | Flat JSON Schema rendered as a form in the client UI |
| URL mode | "Browser redirect" | SEP-1036 experimental; opens a URL and waits |
| `accept` / `decline` / `cancel` | "User response outcomes" | Three branches the server handles |
| Disambiguation | "Pick one" | Common elicitation use case when a tool has N candidates |
| Flat form | "Top-level properties only" | Elicitation schemas cannot nest |
