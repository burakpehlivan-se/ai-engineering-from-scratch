# بناء عميل MCP  اكتشاف، استدعاء، إدارة الجلسات

> معظم محتوى MCP يرسل دروس الخادم ويرفع يد العميل. رمز العميل هو المكان الذي يعيش فيه التنسيق القاسي: عملية التنمو، وتفاوض القدرات، وتدمير قائمة الأدوات عبر خادمات متعددة، ومعينة استدعاءات، وإعادة الاتصال، وحل تصادم مساحة الأسماء. هذا الدروس يبني عميل متعدد الخادم الذي يرفع ثلاثة خادمات MCP مختلفة في مساحة أسماء أداة واحدة مسطحة للنموذج.

**Type:** Build
**Languages:** Python (stdlib, multi-server MCP client)
**Prerequisites:** Phase 13 · 07 (building an MCP server)
**Time:** ~75 minutes

## أهداف التعلم

- إعداد خادم MCP كعملية طفلية ، كاملة `initialize`، وأرسل`notifications/initialized`. . .
- الحفاظ على حالة جلسة لكل خادم (القدرات، قائمة الأدوات، آخر إشارات إشعارية رأى).
- دمج قائمة الأدوات عبر خادمات متعددة إلى مساحة أسماء واحدة مع التعامل مع الصدام.
- توجيه مكالمة أداة إلى الخادم الذي يملكها وإعادة تجميع الرد.

## المشكلة

يستضيف وكيل حقيقي (كلود ديسكوب ، كورسور ، غوز ، جيميني CLI) العديد من خوادم MCP في وقت واحد. قد يكون للمستخدم خادم نظام الملفات ، خادم Postgres ، وخادم GitHub يعمل في نفس الوقت. وظيفة العميل:

1. -أزرق كل خادم
2. ضغط يديك بشكل مستقل
3. اتصل`tools/list`على كل واحد و تسطح النتيجة.
4. عندما يُصدر النموذج`notes_search`،بحث عنه في مساحة الأسماء المدمجة والمسار إلى الخادم المناسب.
5. التعامل مع الإخطارات من أي خادم (`tools/list_changed`) دون حظر.
6. إعادة الاتصال عند فشل النقل

التدفق اليدوي هو ما يفصل بين "الألعاب" و "الخدمة". المعدات الفنية الرسمية تضم هذا، ولكن النموذج العقلي يجب أن يكون لك.

## المفهوم

### التنمو بالعملية الطفولة

`subprocess.Popen`مع`stdin=PIPE, stdout=PIPE, stderr=PIPE`- أُحدد`bufsize=1`و استخدام وضع النص لقراءة خط بعد خط. كل خادم هو عملية واحدة، والعميل يحمل واحد `Popen`التعامل مع كل خادم

### حالة جلسة لكل خادم

أ`Session`يحتوي كل كائن على خادم:

- `process`-القبض البوبين
- `capabilities` ما أعلن عليه الخادم`initialize`. . .
- `tools`آخر مرة`tools/list`النتيجة
- `pending`خريطة لـ "معلومات طلب" إلى وعد/ مستقبلا ينتظر الإجابة.

الطلبات غير متزامنة بطبيعتها`tools/call`يجب أن لا يتم إرسالها إلى الخادم A بينما الخادم B في منتصف المكالمة لا يجب أن يتم حظرها. إما استخدام الأسلاك مع صفوف أو غير متوافق.

### مساحة الأسماء المدمجة

عندما يرى العميل قائمة الأدوات المجمعة، يمكن أن تتصادم الأسماء. قد يظهر كلا الخادمين`search`العميل لديه ثلاثة خيارات:

1. **Prefix by server name.** `notes/search`،`files/search`واضحة ولكن قبيحة
2. **Silent first-come.**الخادم اللاحق `search`يُجاوز المُضاد السابق، مخاطر، يُخفي التصدم.
3. **Collision rejection.**رفض تحميل الخادم الثاني، إخطار المستخدم. آمن لأضافين حساسين للأمن.

تستخدم كلود ديسكوب المسبق على خادم. تستخدم كورسور رفض التصادم مع خطأ واضح. تستخدم VS Code MCP المسبق على خادم أيضًا.

### التوجيه

بعد الاندماج، خرائط طاولة الإرسال`tool_name -> session`. النموذج ينشر مكالمة باسم العميل يجد الجلسة ويكتب `tools/call`الرسالة إلى جهاز الخادم ثم تنتظر الإجابة

### استدعاءات أخذ العينات

إذا أعلن الخادم`sampling`القدرة على`initialize`، قد يرسل`sampling/createMessage`طلب من العميل إدارة ماجستير القانون. يجب على العميل:

1. حظر المزيد من الطلبات إلى هذا الخادم حتى يتم حل العينة، أو أنبوب إذا كان تنفيذها يدعم التزامن.
2. اتصل بمقدمه
3. ارسل الرد الى الخادم

الدروس 11 تغطي أخذ العينات من نهايتها إلى نهايتها.

### إعادة الاتصال

يمكن أن تفشل النقل: الخادم قد تعطلت، نظام التشغيل أدى إلى إعاقة العملية، وتحطمت أنبوب الاستديو. يكتشف العميل EOF على stdout ويعامل الجلسة كمتوفاة. خيارات:

- إعادة تشغيل الخادم بصمت وإعادة ضغط اليدين
- أوضح الفشل للمستخدم. حسناً للخادمات ذات الحالة مع جلسات مرئية للمستخدم.

المرحلة 13 · 09 تغطي أسلوب تعريف إعادة الاتصال HTTP المباشر؛ stdio أبسط.

### رقم الحفاظ على الموقع و رقم الدورة

HTTP المباشر يستخدم `Mcp-Session-Id`عنوان. لا يوجد لدى ستديو معرف جلسة  هوية العملية هي جلسة. الاحتفاظ بالبينغات اختيارية. لا تتحطم أنابيب ستديو في حالة عدم النشاط.

## استخدمها

`code/main.py`يخلق ثلاثة خوادم MCP محاكاة كعمليات فرعية ، يضغط كل منهما ، ويدمج قائمة أدواتها ، ويرسل مكالمات الأدوات إلى اليمين. "الخادمات" هي في الواقع عمليات Python الأخرى التي تعمل على استجابات الألعاب (لا يوجد LLM الحقيقي). تشغيلها لرؤية:

- ثلاث إبتداعات، كل منها مع مجموعة قدرات خاصة به.
- ثلاثة`tools/list`النتائج دمجت في مساحة أسماء 7 أدوات.
- قرار التوجيه بناء على اسم الأداة
- تصادم تم منعه من قبل مساحة الأسماء

ما الذي يجب أن ننظر إليه:

- - نعم`Session`الدراسة تحتفظ بدولة الخادم الواحد نظيفة
- خيط القرئ الخلفي يزيل كل سطر على stdout دون حجب الخيط الرئيسي.
- طاولة الإرسال بسيطة`dict[str, Session]`. . .
- التعامل مع الصدام واضح: عندما يعلن خادمين عن نفس الاسم، يتم تغيير اسم الخادم الأخير مع مقدمة.

## أرسله

هذا الدرس يُنتج`outputs/skill-mcp-client-harness.md`. وبالنظر إلى قائمة إعلانية من خادمات MCP (اسم، أمر، args) ، فإن المهارة تنتج حزمة تنشئها، وتدمج قوائم الأدوات، وتشحن وظيفة توجيه مع حل الصدام.

## التمارين

1. أركض`code/main.py`وراقب سجل إنجاب الخادم، أقتل أحد عمليات الخادم المثبتة مع SIGTERM وراقب كيف الكليين يكتشف EOF ويعبر تلك الجلسة ميتة.

2. تنفيذ مساحة الأسماء التمهيدية عندما يظهر خادمين `search`, إعادة تسمية الثانية`<server>/search`قم بتحديث جدول الإرسال وتحقق من مسار المكالمات بالداول بشكل صحيح

3. إضافة إعادة تشغيل الخادم على شكل مجموعة اتصال: إعادة تشغيل تعريفي على فشل متتالية، حد في 30 ثانية، إصدار إخطار للمستخدم بعد ثلاثة فشل.

4. رسم عميل يدعم 100 خادم MCP متزامن. أي بنية بيانات تحل محل إرشاد الإرسال البسيط؟ (تلميح: محاولة لتسويق أسماء المسبقات، بالإضافة إلى مقياس لعدد الأدوات لكل خادم).

5. نقل العميل إلى MCP Python SDK الرسمي. SDK يلف`stdio_client`و`ClientSession`يجب أن ينخفض الرمز من ~ 200 سطر إلى ~ 40 سطر مع الحفاظ على توجيه متعدد الخادم.

## الشروط الرئيسية

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| MCP client | "The agent host" | Process that spawns servers and orchestrates tool calls |
| Session | "Per-server state" | Capabilities, tool list, and pending-request bookkeeping |
| Merged namespace | "One tool list" | Flat set of tool names across all active servers |
| Namespace collision | "Two servers same tool" | Client must prefix, reject, or first-come the duplicate |
| Routing | "Who gets this call?" | Dispatch from tool name to owning server |
| Background reader | "Non-blocking stdout" | Thread or task that drains server stdout into a queue |
| Sampling callback | "LLM-as-a-service" | Client handler for `sampling/createMessage` from server |
| `notifications/*_changed` | "Primitive mutated" | Signal the client must re-discover or re-read |
| Reconnection policy | "When server dies" | Restart semantics when transport fails |
| Stdio session | "Process = session" | No session id; child process lifetime is the session |
