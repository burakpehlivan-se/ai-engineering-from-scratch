# نقلات MCP  stdio vs Streamable HTTP vs SSE الهجرة

> يعمل stdio محلياً ولا في أي مكان آخر. HTTP المباشر (2025-03-26) هو المعيار عن بعد. يتم إزالة نقل HTTP + SSE القديم وإزالة في منتصف عام 2026. يكلّف اختيار النقل الخطأ الهجرة.

**Type:** Learn
**Languages:** Python (stdlib, Streamable HTTP endpoint skeleton)
**Prerequisites:** Phase 13 · 07, 08 (MCP server and client)
**Time:** ~45 minutes

## أهداف التعلم

- اختيار بين stdio و Streamable HTTP بناء على شكل النشر (المحلي مقابل عن بعد، عملية واحدة مقابل أسطول).
- تنفيذ نمط HTTP المتداول لمنتصف واحد: POST للطلبات، GET لتدفق الجلسة.
- التنفيذ`Origin`التحقق من التحقق من التحقق من التحقق من التحقق من التحقق من التحقق من النظام الأساسي
- نقل خادم HTTP + SSE القديم إلى HTTP المباشر قبل أواخر إزالة منتصف عام 2026.

## المشكلة

كان أول نقل بعيد من MCP (2024-11) HTTP + SSE: نقطتين نهائية ، واحدة لـ POSTs العميل و قناة Server-Sent-Events واحدة للدفق من خادم إلى عميل. عملت. كانت غير مساعدة أيضًا: نقطتين نهائية في كل جلسة ، والخزينات المحفظة المكسورة أمام بعض CDN ، والاعتماد القوي على اتصالات SSE طويلة الأمد التي تنتهي بها بعض WAFات بشكل عدواني.

تم استبدال مواصفات 2025-03-26 بـ Streamable HTTP: نقطة نهاية واحدة ، POST لطلبات العملاء ، GET لإنشاء سلسلة جلسات ، كلاهما يشارك `Mcp-Session-Id`كل خادم تم بناؤه أو هجره منذ ذلك الحين يستخدم HTTP المباشر. يتم استئصال وضع SSE القديم  أصلستيان روفو إزالتها 30 يونيو 2026; كيبولا 1 أبريل 2026; معظم الخوادم المؤسسية المتبقية بحلول نهاية عام 2026.

و ستديو لا يزال مهمًا للخادمات المحلية. كلود ديسكوب، VS Code، وكل خادمات عميل على شكل IDE تنشأ عبر ستديو. النموذج العقلي الصحيح: ستديو "هذه الآلة" ، HTTP المباشر "على الشبكة". لا يوجد تعديل.

## المفهوم

### الاستديو

- النقل من خلال العمليات الطفولة العميل يولد الخادم، يتواصل عبر stdin/stdout
- كائن JSON واحد لكل سطر، خط جديد محدد
- لا يوجد هوية جلسة، هووية العملية هي الجلسة.
- لا حاجة إلى تأمين (يتم إرث الطفل حدود الثقة من الوالد).
- لا تستخدم أبداً للخادمات النائية  ستحتاج إلى SSH أو socat للتنيل، عندها استخدم HTTP المباشر.

### HTTP المباشر

نقطة نهاية واحدة`/mcp`يدعم ثلاثة طرق HTTP:

- **POST /mcp.**يقوم العميل بإرسال رسالة JSON-RPC. يستجيب الخادم إما برد واحد من JSON، أو سلسلة SSE من استجابات واحدة أو أكثر (فائدة للردود المفروضة والإشعارات المتعلقة بهذا الطلب).
- **GET /mcp.**يفتح العميل قناة SSE طويلة الأمد. يستخدمها الخادم لطلبات الخادم إلى العميل (المعينة، الإخطارات، الإجراءات).
- **DELETE /mcp.**العميل ينهي الجلسة صراحة

يتم تحديد الجلسات من قبل `Mcp-Session-Id`عنوان يضع الخادم على الاستجابة الأولى والعميل يتردد على كل طلب لاحقا. يجب أن تكون هويات الدورة عشوائية بشكل رمزي (128+ بت) ؛ يتم رفض هويات المستخدم المختارة لأجل السلامة.

### نقطة نهاية واحدة مقابل اثنين

لا يزال وضع نقطتين نهاية من المواصفات القديمة قابلاً للتصوير في عام 2026  يعلن المواصفات أنه "متوافق مع التراث". ولكن يجب أن تكون جميع الخوادم الجديدة نقطة نهاية واحدة. تنبعث SDKs الرسمية نقطة نهاية واحدة. استخدم وضع التراث فقط عند التحدث إلى جهاز تحويل غير منتقل.

### `Origin`التحقق من التحقق والتحقق من DNS

المتصفحات ليست عملاء MCP (اليوم) ، ولكن يمكن للمهاجمين تصميم صفحة ويب التي تقنع المتصفح بـ POST إلى `localhost:1234/mcp` حيث يستمع خادم MCP المحلي للمستخدم. إذا لم يقرخ الخادم `Origin`سياسة نفس المنشأ من المتصفح لن تنقذها لأن `Origin: http://evil.com`هو مصدر متقاطع صالح.

تطلب مواصفات 2025-11-25 من الخوادم رفض طلبات`Origin`ليست في قائمة السماح.`https://claude.ai`،`vscode-webview://*`) والإضافة المحلية لـ"lobalhost" المتغيرات للمواصفات المحلية.

### دورة حياة ID الجلسة

1. العميل يرسل طلباً أولياً دون`Mcp-Session-Id`. . .
2. الخادم يعطي الهوية عشوائية، مجموعات `Mcp-Session-Id`على عنوان الاستجابة
3. العميل يعيد هذا العنوان على جميع الطلبات اللاحقة و على `GET /mcp`للجريان
4. يمكن إلغاء الجلسة من قبل الخادم؛ يرى العميل 404 على الطلبات اللاحقة ويجب إعادة تشغيلها.
5. العميل يمكنه حذف الجلسة بشكل صريح لإغلاق نظيف

### صنعة التوافق الخلفي

عميل يريد دعم كلا من الخوادم القديمة والجديدة:

1. - لا .`/mcp`. . .
2. إذا كان الإجابة هي`200 OK`مع JSON أو SSE، هذا هو HTTP Streamable.
3. إذا كان الإجابة هي`200 OK`مع`Content-Type: text/event-stream`و (أ)`Location`الرأس الذي يشير إلى نقطة نهاية ثانوية، وهذا هو HTTP + SSE التراثي؛ اتبع `Location`. . .

### Cloudflare, ngrok, و استضافة

إنتاج خادمات MCP عن بعد في عام 2026 تعمل على Cloudflare Workers (مع SDK وكلاء MCP الخاصة بهم) ، وظائف Vercel ، أو Node / Python المحفظة. المفتاح: يجب أن يدعم استضافةك اتصالات HTTP طويلة الأمد لـ SSE GET. تصل مستويات Vercel المجانية إلى 10 ثواني وهي غير مناسبة. يعمل Cloudflare Workers على دعم التدفقات غير المحددة.

### تركيب البوابة

عندما تقوم بتقديم العديد من خوادم MCP مع بوابة (مرحلة 13 · 17) ، فإن البوابة هي نقطة نهاية HTTP واحدة يمكن تشغيلها التي تقوم بإعادة كتابة أرقام المواقف والمتعددات فوق التيار. يتم دمج الأدوات في طبقة البوابة؛ يرى العميل خادمًا منطقيًا واحدًا.

### أساليب فشل النقل

- **stdio SIGPIPE.**موت الطفل في منتصف الكتابة يرفع SIGPIPE، يجب أن تخرج الخوادم نظيفة. يجب على العملاء اكتشاف EOF وتسجيل جلسة ميتة.
- **HTTP 502 / 504.**تقوم Cloudflare و nginx وغيرها من الأوكيلات بإصدار هذه الإصدارات عند فشل التيار. يجب على عملاء HTTP المباشرين تجربة مرة أخرى بعد إعادة التوصيل القصير.
- **SSE connection drop.**تُغلق TCP RST، أو توقيت الوقت بالوكيل، أو تغيير شبكة العميل التيار. يقوم العميل بإعادة الاتصال مع `Mcp-Session-Id`و اخيارية`last-event-id`ليتم استئنافها
- **Session revocation.**الخادم يجعلها غير صالحة، العميل يرى 404 عند الطلب التالي. يجب على العميل أن يضغط يدًا مرة أخرى.
- **Clock skew.**حسابات الموارد-TTL على العميل تختلف عن الخادم. يجب على العميل التعامل مع طوابع الوقت الخادم باعتبارها مؤكدة.

### متى تخطي HTTP المباشر

بعض المؤسسات تقوم بتنفيذ خوادم MCP وراء gRPC أو نقلات خطة الرسائل داخل شبكاتها الخاصة. هذا غير قياسي  لا تعرّف مواصفات MCP هذه رسمياً. يمكن لبرامج البوابات تعريض سطح HTTP المباشر لعملاء MCP أثناء استخدام gRPC داخلياً. الحفاظ على مواصفات سطح الخارجية ؛ تمتلك البوابة الترجمة.

## التمارين

1. أركض`code/main.py`. تحرير`initialize`من`curl`ولاحظوا`Mcp-Session-Id`عنوان الاستجابة. إرسال طلب ثان يتردد في العنوان والتحقق من استمرارية الجلسة.

2. إضافة عامل GET الذي يفتح تدفق SSE. إرسال واحد `notifications/progress`حدث كل خمس ثواني. إعادة الاتصال بإعادة التوصيل مع نفس عنوان الجلسة وتأكيد الخادم يقبل ذلك.

3. تنفيذ`last-event-id`على إعادة الاتصال، إعادة تشغيل أي أحداث تم إنشاؤها منذ ذلك الهوية.

4. التمديد`Origin`التحقق من التحقق من الصحة الدولية`https://*.example.com`) و تأكيد أنها تقبل`https://app.example.com`لكن يرفض`https://evil.example.com.attacker.net`. . .

5. خذ خادم HTTP + SSE القديم من السجل الرسمي (هناك العديد) و رسم الهجرة: ما هي التغييرات في معالجة النقاط النهائية ، وتوليد معرف الجلسة ، وترجمة العنوان.

## الشروط الرئيسية

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| stdio transport | "Local child process" | JSON-RPC over stdin/stdout, newline-delimited |
| Streamable HTTP | "The remote transport" | Single-endpoint POST + GET + optional SSE, 2025-03-26 spec |
| HTTP+SSE | "Legacy" | Two-endpoint model being removed in mid-2026 |
| `Mcp-Session-Id` | "Session header" | Server-assigned random id echoed on every subsequent request |
| `Origin` allowlist | "DNS-rebinding defense" | Reject requests whose Origin is not approved |
| Single endpoint | "One URL" | `/mcp` handles POST / GET / DELETE for all session operations |
| `last-event-id` | "SSE replay" | Header used to resume a dropped stream without missing events |
| Backwards-compat probe | "Old vs new detection" | Client response-shape check that auto-selects transport |
| Long-lived HTTP | "SSE streaming" | Server pushes events for minutes or hours on one TCP connection |
| Session revocation | "Force re-init" | Server invalidates a session id; client must handshake again |
